Remarque importante

L'utilisation de BallyFA peut endommager votre flipper. Comme il s'agit d'un projet privé SANS intérêt commercial, l'auteur décline toute responsabilité pour les dommages qui pourraient résulter de l'utilisation de BallyFA !

1. Introduction

BallyFA utilise un FPGA (bon marché) qui émule le matériel d'une MPU Bally -17 / -35 : le processeur 6800, les deux PIA 6821, la RAM 6810, la RAM CMOS 5101 et les ROM de jeu U2 et U6. L'exception est le connecteur « J5 » : BallyFA ne peut pas être utilisé sur les jeux Stern dont la carte son est raccordée par J5. Pour ces jeux, il existe SternFA.

BallyFA est un projet 100 % amateur. Cela rend la solution bon marché : selon l'endroit où vous achetez les composants, vous pouvez construire votre MPU Bally de remplacement pour moins de 50 €.

De quoi avez-vous besoin ?

  • Des notions de base en soudure (la plupart des fournisseurs livrent les composants CMS déjà montés)
  • La possibilité de lire et d'écrire des cartes micro SD
  • Un PC avec un port USB et un USB Blaster pour programmer le FPGA

Trois choses sont bonnes à savoir avant de commencer :

  • Les ROM de jeu sont rechargées à chaque mise sous tension, depuis la carte SD. Les cartes équipées d'une carte FPGA Cyclone IV ou Cyclone 10 peuvent aussi les lire dans leur flash de configuration quand aucune carte SD n'est insérée (à partir de x.30, chapitre 5.3).
  • Les interrupteurs DIP sont lus au démarrage. Après en avoir changé un, éteignez puis rallumez le flipper.
  • Le programme FPGA dépend de votre carte. La carte de base (HW 1.x ou HW 2.x) et la carte FPGA (Cyclone II, Cyclone IV v3.x, Cyclone IV v4.x, Cyclone 10) demandent chacune leur propre fichier - voir le chapitre 9. La version affichée au démarrage indique lequel tourne.

2. Démarrage rapide

  1. Téléchargez la dernière image de carte SD et le programme FPGA de votre carte sur lisy.dev (chapitre 9)
  2. Écrivez l'image sur une carte micro SD et insérez la carte dans la platine
  3. Programmez le FPGA
  4. Réglez le banc DIP S1 « choix du jeu » selon votre flipper (annexe A)
  5. Laissez pour commencer tout le banc DIP S2 « options » sur OFF
  6. Remplacez votre MPU Bally d'origine par BallyFA
  7. Allumez le flipper
  8. Observez les afficheurs pendant les premières secondes et vérifiez que la version et le numéro de jeu sont ceux attendus (chapitre 5.1)
  9. Amusez-vous

La première programmation de la carte est décrite sur mon site : https://lisy.dev/documentation-01.html

3. Installation

Les cartes BallyFA ont les mêmes connecteurs et les mêmes trous de fixation que les MPU Bally/Stern d'origine ; le remplacement se fait donc en quelques secondes. Éteignez le flipper, retirez la MPU d'origine, mettez BallyFA en place, c'est fini.

4. Réglage des interrupteurs DIP

4.1. Banc DIP S1 : choix du jeu

Ici, vous choisissez le jeu que BallyFA doit exécuter. Cela dépend des ROM présentes sur la carte SD ; l'annexe A liste le contenu de l'image actuelle, le chapitre 10 explique la structure de la carte.

La position des interrupteurs est simplement le numéro du jeu en binaire, S1 étant le bit de poids faible :

Interrupteur S1 S2 S3 S4 S5 S6 S7 S8
ajoute 1 2 4 8 16 32 64 128

ON = la valeur est ajoutée. Le jeu 36 (ELEKTRA) correspond donc à 4 + 32 = S3 et S6 sur ON, tout le reste sur OFF. L'annexe A détaille cela pour chaque jeu.

4.2. Banc DIP S2 : options

Le réglage par défaut est tout sur OFF.

4.2.1. S2-Dip1 -> émulateur de zero cross

Une MPU Bally a besoin d'un signal « zero cross » (passage par zéro) pour fonctionner correctement ; ce signal provient de l'alimentation 12 volts. Sa présence est vérifiée au démarrage.

Avec Dip1 sur ON, BallyFA génère lui-même ce signal ; pour des essais sur l'établi, une alimentation 5 volts suffit alors. Avec un zero cross émulé, la temporisation est différente - à utiliser sur l'établi, pas dans le flipper.

4.2.2. S2-Dip2 -> sauvegarde continue du nvram

BallyFA enregistre le contenu du nvram (meilleurs scores et réglages étendus) dans une EEPROM ou une FRAM. Chaque jeu y dispose de sa propre zone.

En jeu normal, le contenu du nvram est sauvegardé automatiquement - déclenché par l'interrupteur de test, le relais de fin de partie (game over) et le bouton de crédit.

Avec Dip2 sur ON, BallyFA sauvegarde en plus tout le contenu du nvram chaque seconde. C'est prévu pour les essais sur l'établi.

Attention : ne mettez Dip2 sur ON que sur une carte équipée d'une FRAM. Une EEPROM ne supporte qu'un nombre limité de cycles d'écriture, et une sauvegarde chaque seconde l'use. Une FRAM n'y est pas sensible. (Modifié avec le logiciel x.23 ; auparavant, Dip2 déclenchait une sauvegarde unique.)

4.2.3. S2-Dip3 -> non utilisé

Non implémenté, laissez-le sur OFF.

4.2.4. S2-Dip4 -> anti-scintillement pour les jeux à LED

Avec Dip4 sur ON, BallyFA modifie la temporisation du signal zero cross. Les jeux Bally sont connus pour faire scintiller les ampoules de remplacement à LED ; en général, chaque LED a besoin d'une résistance en parallèle pour y remédier. Avec cette option, les LED ne scintillent plus, même sans ces résistances.

4.2.5. S2-Dip5 -> monnayeur

Avec Dip5 sur ON, l'entrée du monnayeur est activée (chapitre 7). Ne l'activez pas si aucun monnayeur n'est raccordé.

4.2.6. S2-Dip6 -> initialisation du nvram

Avec Dip6 sur ON, BallyFA remet à zéro le nvram du jeu choisi au démarrage. C'est utile si vous voulez effacer tout le contenu de la RAM.

Remettez-le ensuite sur OFF et éteignez puis rallumez - sinon le flipper efface ses réglages à chaque démarrage.

5. Séquence de démarrage

5.1. Phase 1 : l'affichage d'informations

Juste après avoir allumé le flipper équipé de BallyFA, vous voyez ceci sur les afficheurs, avant que le moindre code de jeu ne s'exécute :

Afficheur Montre
Joueur 1 la version du programme FPGA en cours, par ex. 4 3 0. Le premier chiffre désigne la carte FPGA, un 2 en tête signifie carte de base HW 2.x - par ex. 2 4 3 0 (chapitre 9)
Joueur 2 le numéro de jeu choisi avec S1
Joueur 3 050963 - l'identifiant lisy.dev des MPU à base de FPGA. Il est fixe et indique seulement que la liaison vers les afficheurs fonctionne
Joueur 4 vide si le jeu vient de la carte SD. S'il vient de la flash de configuration : le numéro du jeu (chapitre 5.3)
Crédit / état un compteur qui décompte à chaque clignotement de la LED verte « Bally »

Vérifiez les joueurs 1 et 2 à chaque premier démarrage. Ils indiquent si le bon programme est dans le FPGA et si les interrupteurs de choix du jeu sont réglés comme vous le pensiez.

Après les cinq premiers clignotements, les afficheurs s'éteignent jusqu'à ce que le code du jeu en prenne le contrôle.

5.2. Phase 2 : lecture de la carte SD

BallyFA lit la ROM du jeu choisi sur la carte SD. En cas d'échec, la LED rouge « SD card error » clignote un code - un clignotement par seconde, le nombre de clignotements indique à quelle étape de l'initialisation de la carte l'échec s'est produit - puis reste allumée. Le CPU n'est pas démarré.

Si la lecture réussit, la LED rouge reste éteinte.

5.3. Fonctionnement sans carte SD (x.30, Cyclone IV et Cyclone 10)

Nouveau avec le logiciel x.30. Si aucune carte SD ne répond, une carte équipée d'une carte FPGA Cyclone IV ou Cyclone 10 ne s'arrête pas là : elle charge le jeu choisi depuis la flash de configuration (EPCS16) à partir de laquelle le FPGA démarre lui-même, sous le même numéro de jeu que sur la carte SD.

  • Un démarrage depuis la flash se reconnaît à l'afficheur 4 : pendant l'affichage d'informations, il montre le numéro du jeu. Avec une carte SD, il reste vide.
  • Pour des raisons de droits d'auteur, les fichiers publiés sur lisy.dev ne contiennent aucun jeu dans la flash. Sans carte, le démarrage se termine alors par l'erreur 8 : l'afficheur 4 montre un 8 devant le numéro du jeu, la LED rouge clignote 8 fois, fait une pause de 2 secondes et recommence, et le CPU ne démarre pas.
  • L'erreur 8 apparaît aussi pour un numéro de jeu absent de la flash. Il y a de la place pour 192 jeux (0 à 191) ; l'image flash construite à partir de la carte SD v111 contient les 142 jeux de l'annexe A.
  • Comment les jeux arrivent dans la flash : chapitre 11.
  • Les cartes équipées d'une carte FPGA Cyclone II n'ont pas de repli sur la flash - elles ont toujours besoin de la carte SD.

5.4. Phase 3 : exécution du programme

Le code choisi avec le banc DIP « choix du jeu » est exécuté. Il lance la séquence de démarrage Bally normale en faisant clignoter la LED verte « Bally ». Si le code tourne (des interruptions régulières arrivent), la LED verte « ON » s'allume.

À partir de là, le flipper se comporte comme avec l'original.

7. Monnayeur (optionnel)

Vous pouvez raccorder un monnayeur standard (par ex. NRI-G13) au connecteur situé sous la carte BallyFA. Pour activer le monnayeur, mettez Dip5 du banc DIP « options » sur ON.

Correspondance entre interrupteurs Bally et canaux pour BallyFA :

Interrupteur Bally Monnayeur Canal du monnayeur
#9 fente droite canal 6
#10 fente gauche canal 4
#11 fente centrale canal 5

La sortie de blocage des pièces (coin lockout) du jeu commande aussi l'entrée de blocage du monnayeur.

8. Connexion USB (matériel 2.x)

La carte de base HW 2.x possède un connecteur USB (convertisseur série CH340). Derrière, le FPGA utilise le protocole lisy_api pour le Mission Pinball Framework (MPF). Il s'agit d'une bêta : pour l'instant, il ne répond qu'à la détection du matériel par MPF. Le connecteur USB n'est pas nécessaire pour jouer normalement.

Les cartes HW 1.x n'ont pas de connecteur USB.

9. Variantes de carte et programme FPGA

Le même design fonctionne sur huit combinaisons de carte de base et de carte FPGA, et le programme FPGA n'est pas interchangeable entre elles - le brochage diffère, et un mauvais programme n'affichera au mieux rien et pilotera au pire les mauvaises broches.

Le FPGA est configuré depuis une mémoire de configuration série, le programme reste donc en place après une coupure de courant. On le programme une fois, pas à chaque démarrage.

10. Structure de la carte SD

En raison des limites de la routine de lecture SD dans le FPGA (elle lit des numéros de secteur fixes au lieu de chercher des noms de fichier), il faut utiliser mon image de carte SD (128 Mo). Vous pouvez écrire l'image sur la carte SD de votre choix avec un outil de copie brute (par exemple Win32DiskImager, balenaEtcher ou dd).

Avec le choix du jeu entièrement sur « 0 », BallyFA lit la première image ROM au secteur 660. Avec mon image BallyFA de 128 Mo, c'est l'emplacement du premier fichier écrit sur une carte SD vide. Chaque jeu occupe 16 secteurs, le jeu n commence donc au secteur 660 + n x 16.

Les ROM Bally doivent être au format « U2 / U6 », de 4 Ko chacune ; une image ROM utilisable par BallyFA fait donc 8 Ko : d'abord U2, puis U6.

10.1. L'image BallyFA

Mon image de carte SD BallyFA (v111) contient presque toutes les ROM disponibles - 142 jeux. La liste des jeux est à l'annexe A, une description des ROM spéciales à l'annexe B.

10.2. Utiliser ses propres ROM

Supposons que vous ayez un flipper Bally KISS avec les fichiers ROM U2 : KISS2732.U2 et U6 : 720-3032.U6. Vous créez votre ROM BallyFA en ligne de commande Windows avec :

copy /b KISS2732.U2 + 720-3032.U6 BallyFA_Kiss.rom

Supprimez TOUS les fichiers de votre carte SD BallyFA et copiez-y BallyFA_Kiss.rom. En réglant le choix du jeu sur « 0 », c'est maintenant KISS qui tourne.

11. ROM de jeu dans la flash du FPGA

Les cartes équipées d'une carte FPGA Cyclone IV ou Cyclone 10 démarrent depuis une puce flash de 2 Mo (EPCS16). Le programme FPGA occupe les 512 premiers Ko ; à partir de l'adresse 080000h, il y a de la place pour 192 jeux de 8 Ko chacun, octet pour octet les mêmes images que sur la carte SD :

adresse flash 080000h + numéro de jeu x 2000h    ROM de jeu de 8 Ko (U2 + U6)

Les ROM sont protégées par le droit d'auteur et ne peuvent donc pas faire partie du téléchargement. Vous les y placez vous-même, à partir d'une image de votre carte SD. Dans l'arborescence source de BallyFA (github.com/bontango/BallyFa), exécutez

powershell -File scripts\build.ps1 <variant> -RomImage <path>\BallyFA_SD_111.img

par exemple avec hw2_cyclone_10 ; les noms des variantes figurent dans le README.md du dépôt. Cela construit le programme FPGA et le regroupe avec tous les jeux de l'image dans un seul fichier, variants\<variant>\output_files\bally_roms.jic. Programmez-le avec le Quartus Programmer à la place du .jic normal.

Dès lors, la carte fonctionne sans carte SD. Si une carte SD est insérée, elle a toujours la priorité ; vous pouvez donc toujours essayer d'autres ROM depuis une carte sans toucher à la flash.

Gardez ce fichier pour vous. Il contient les ROM de jeu et ne doit pas être diffusé.

12. Historique des versions

La version affichée au démarrage est [2] carte . sous-version, par ex. 2 4.23 pour HW 2.x avec Cyclone 10 et le logiciel x.23.

x.11 Dip4 : zero cross retardé contre le scintillement des LED (ne fonctionne pas encore)
