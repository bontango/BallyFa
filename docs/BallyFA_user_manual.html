Important remark

By using BallyFA it is possible to damage your pinball machine. As this is a private project with NO commercial interest the author accepts no liability for any damage that may arise by using BallyFA!

1. Introduction

BallyFA uses a (low cost) FPGA which emulates the hardware of a Bally -17 / -35 MPU: the 6800 processor, the two PIA 6821, the 6810 ram, the 5101 CMOS ram and the game roms U2 and U6. The exception is connector 'J5', which means BallyFA cannot be used with Stern games that have their sound board connected via J5. For those games there is SternFA.

BallyFA is a 100% hobby project. This makes the solution cheap; depending on where you buy your components it is possible to build your Bally replacement MPU for less than 50 €.

What do you need?

  • Basic soldering skills (SMD components can be ordered pre-assembled in most shops)
  • The possibility to read/write micro SD cards
  • A PC with a USB port and a USB Blaster in order to be able to program the FPGA

Three things are worth knowing before you begin:

  • The game roms are loaded anew at every power-up, from the SD card. Boards with a Cyclone IV or Cyclone 10 FPGA board can also take them from their configuration flash when no card is inserted (from x.30, chapter 5.3).
  • The DIP switches are read at boot. After changing one, switch the machine off and on.
  • The FPGA program depends on your board. Base board (HW 1.x or HW 2.x) and FPGA board (Cyclone II, Cyclone IV v3.x, Cyclone IV v4.x, Cyclone 10) each need their own file - see chapter 9. The version shown at boot tells you which one is running.

2. Quickstart

  1. Download the latest SD card image and the FPGA program for your board from lisy.dev (chapter 9)
  2. Write the image to a micro SD card and put the card into the board
  3. Program the FPGA
  4. Configure DIP bank S1 'game select' according to your pinball (Appendix A)
  5. Leave DIP bank S2 'options' all OFF for a start
  6. Replace your original Bally MPU with BallyFA
  7. Switch the game ON
  8. Watch the displays for the first seconds and check that version and game number are what you expect (chapter 5.1)
  9. Enjoy

Documentation on how to program your board for the first time can be found on my website: https://lisy.dev/documentation-01.html

3. Installation

BallyFA boards have the same connectors and the same mounting holes as the original Bally/Stern MPUs, so replacing the board can be done in seconds. Switch the machine off, pull the original MPU, put BallyFA in, done.

4. DIP switch settings

4.1. DIP switch S1: game select

Here you select which game BallyFA should run. This depends on the roms placed on the SD card; Appendix A lists what the current image contains, chapter 10 explains the structure of the card.

The switch pattern is simply the game number in binary, S1 being the lowest bit:

Switch S1 S2 S3 S4 S5 S6 S7 S8
adds 1 2 4 8 16 32 64 128

ON = the value is added. Game 36 (ELEKTRA) is therefore 4 + 32 = S3 and S6 ON, everything else OFF. Appendix A spells this out for every game.

4.2. DIP switch S2: options

Default setting is all OFF.

4.2.1. S2-Dip1 -> zero cross emulator

A Bally MPU needs a 'zero cross' signal in order to work properly; this signal comes from the 12 volt power supply. The existence of this signal is checked during boot.

With Dip1 ON BallyFA emulates this signal, so for testing on the bench you only need a 5 volt supply. Note that the timing is different with emulated zero cross - use it on the bench, not in the machine.

4.2.2. S2-Dip2 -> save nvram content continuously

BallyFA uses an EEPROM or FRAM to save the nvram content (high scores and extended settings). Each game has its own area in it.

During normal gameplay the nvram content is saved automatically - triggered by the test switch, the game over relay and the credit button.

With Dip2 ON BallyFA additionally saves the complete nvram content every second. This is meant for bench testing.

Caution: only use Dip2 ON on a board with FRAM. An EEPROM has a limited number of write cycles, and saving every second wears it out. FRAM does not care. (This changed in software x.23; before, Dip2 triggered a single save.)

4.2.3. S2-Dip3 -> not used

Not implemented, leave it OFF.

4.2.4. S2-Dip4 -> anti flicker for games with LEDs

With Dip4 ON BallyFA changes the timing of the zero cross signal. Bally games are known for flickering LED replacement lamps; usually each LED needs a resistor in parallel to solve this. With this option the LEDs are flicker free without the additional resistors.

4.2.5. S2-Dip5 -> coin validator

With Dip5 ON the coin validator input is activated (chapter 7). Do not activate this when no validator is connected.

4.2.6. S2-Dip6 -> init nvram

With Dip6 ON BallyFA initialises the nvram of the selected game to zero during boot. This is useful if you want to reset all ram content.

Set it back to OFF and power cycle afterwards - otherwise the machine will wipe its settings on every start.

5. Boot sequence

5.1. Phase 1: the info display

Immediately after switching on the pinball with BallyFA inserted you will see the following on the displays of your pinball machine, before any game code runs:

Display Shows
Player 1 version of the FPGA program running, e.g. 4 3 0. The first digit is the FPGA board, a leading 2 means base board HW 2.x - e.g. 2 4 3 0 (chapter 9)
Player 2 the selected game number from S1
Player 3 050963 - the lisy.dev identifier for FPGA based MPUs. It is fixed and only tells you that the display path works
Player 4 empty when the game came from the SD card. When it came from the configuration flash: the game number (chapter 5.3)
Credit / status a counter, counting down with each blink of the green 'Bally' LED

Check player 1 and player 2 at every first start. They tell you whether the right program is in the FPGA and whether the game select switches are set to what you meant.

After the first five blinks the displays are blanked until the game code takes them over.

5.2. Phase 2: SD card read

BallyFA reads the rom of the selected game from the SD card. If this fails, the red LED 'SD card error' blinks a code - one blink per second, the number of blinks tells at which step of the card initialisation it failed - and then stays lit. The CPU is not started.

If the read succeeds, the red LED stays dark.

5.3. Running without SD card (x.30, Cyclone IV and Cyclone 10)

New with software x.30. If no SD card answers, a board with a Cyclone IV or Cyclone 10 FPGA board does not stop there: it loads the selected game from the configuration flash (EPCS16) the FPGA itself boots from, under the same game number as on the card.

  • You can tell a flash boot by display 4: during the info display it shows the game number. With an SD card it stays empty.
  • The release files on lisy.dev carry no games in the flash, for copyright reasons. Without a card the boot then ends with error 8: display 4 shows an 8 in front of the game number, the red LED blinks 8 times, pauses 2 seconds and repeats, and the CPU does not start.
  • Error 8 also appears for a game number that is not in the flash. There is room for 192 games (0 to 191); the flash image built from SD card v111 holds the 142 games of Appendix A.
  • How the games get into the flash: chapter 11.
  • Boards with a Cyclone II FPGA board have no flash fallback - they always need the SD card.

5.4. Phase 3: program execution

The code selected with the DIP switch 'game select' is executed. This starts the normal Bally boot sequence by blinking the green 'Bally' LED. If the code runs (regular interrupts are seen) the green 'ON' LED goes on.

From here on, the machine behaves like the original.

6. The LEDs on the board

LED Meaning
SD card error (red) dark is the normal state. Blinking then steady = the SD card could not be read (5.2). 8 blinks in a row with a pause = error 8, game not in the flash (5.3)
zero cross shows the zero cross signal from the power supply. If it is missing, look at the rectifier board, not at BallyFA
Bally (green) the LED of the original MPU: blinks during the boot sequence of the game code
ON (green) lit while the game code runs and the interrupts come regularly

7. Coin validator (optional)

You can connect a standard coin validator (e.g. NRI-G13) to the connector on the bottom of the BallyFA PCB. To activate the coin validator set Dip5 of the 'options' DIP switch bank to ON.

Bally switch / channel assignments for BallyFA:

Bally switch Chute Validator channel
#9 right chute channel 6
#10 left chute channel 4
#11 middle chute channel 5

The coin lockout output of the game also drives the lockout input of the validator.

8. USB connection (hardware 2.x)

Base board HW 2.x has a USB connector (CH340 serial converter). Behind it the FPGA runs the lisy_api protocol for the Mission Pinball Framework (MPF). This is a beta: so far it only answers the MPF hardware scan. For normal play the USB connector is not needed.

HW 1.x boards have no USB connector.

9. Board variants and the FPGA program

The info display tells you which program is running: on player display 1 the leading 2 stands for base board HW 2.x, the next digit for the FPGA board, the last two for the software version. The files are in the BallyFA software repository, in the same folder structure:

https://lisy.dev/swrep/BallyFA/software/

How to install the programmer software and the USB Blaster driver and how to program the FPGA is described on https://lisy.dev/documentation-01.html. The FPGA is configured from a serial configuration device, so the program stays in place after a power cycle. You program it once, not at every start.

10. Structure of the SD card

Due to limitations of the SD card read routine in the FPGA (it reads fixed sector numbers instead of looking for file names) it is necessary to use my SD card image (128 MByte). You can write the image to a SD card of your choice with a raw imaging tool (for example Win32DiskImager, balenaEtcher or dd).

With game select all '0' BallyFA reads the first rom image at sector number 660. With my 128 MB BallyFA image this is the location of the first file you write to an empty SD card. Every game occupies 16 sectors, so game n starts at sector 660 + n x 16.

The Bally roms need to be in the 'U2 / U6' format, 4 KByte each, so one rom image usable for BallyFA is 8 KByte in size: first U2, then U6.

10.1. BallyFA image

My BallyFA SD card image (v111) has almost all available roms 'on board' - 142 games. See Appendix A for the game list and Appendix B for a description of the special roms.

10.2. Use your own roms

Let us assume you have a Bally KISS pinball with the rom files U2: KISS2732.U2 and U6: 720-3032.U6. You can create your BallyFA rom on the Windows command line with:

copy /b KISS2732.U2 + 720-3032.U6 BallyFA_Kiss.rom

Delete ALL files on your BallyFA SD card and copy BallyFA_Kiss.rom to it. Now, by selecting '0' on game select, you will have a KISS pinball running.

11. Game roms in the FPGA flash

Boards with a Cyclone IV or Cyclone 10 FPGA board boot from a 2 MByte flash chip (EPCS16). The FPGA program takes the first 512 KByte; from address 080000h on there is room for 192 games of 8 KByte each, byte for byte the same images as on the SD card:

flash address 080000h + game number x 2000h    8 KByte game rom (U2 + U6)

The roms are copyrighted, so they cannot be part of the download. You put them there yourself, from an image of your SD card. In the BallyFA source tree (github.com/bontango/BallyFa) run

powershell -File scripts\build.ps1 <variant> -RomImage <path>\BallyFA_SD_111.img

for example hw2_cyclone_10; the variant names are listed in the README.md there. This builds the FPGA program and puts it together with every game of the image into one file, variants\<variant>\output_files\bally_roms.jic. Program it with the Quartus Programmer instead of the normal .jic.

From then on the board runs without SD card. With a card in the slot the card always wins, so you can still try other roms from a card without touching the flash.

Keep that file to yourself. It contains the game roms and must not be passed on.
